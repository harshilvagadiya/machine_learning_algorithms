## 1. The Multinomial Generative Story in NLP

In text classification (e.g. spam detection, sentiment analysis, document topic categorisation), a document is modeled as a "bag of words" generated by repeatedly drawing tokens from a discrete vocabulary $V$ of size $D$.

Let $\mathbf{x} = [x_1, x_2, \dots, x_D]^T$ where $x_j$ represents the frequency count of word $j$ in the document.

The conditional likelihood follows the **Multinomial Probability Mass Function**:

$$P(\mathbf{x} \mid y = c) = \frac{(\sum_{j=1}^D x_j)!}{\prod_{j=1}^D x_j!} \prod_{j=1}^{D} p_{cj}^{x_j}$$

Where:
* $p_{cj}$: The probability that word $j$ appears when generating a document of class $c$.
* $\frac{(\sum x_j)!}{\prod x_j!}$: The multinomial coefficient (multiset permutations of words).

```
                 MULTINOMIAL BAG-OF-WORDS GENERATION
                 
    Class = SPAM (c=1)
    Vocabulary Bag: [ "free": 0.08, "win": 0.05, "cash": 0.07, "the": 0.02 ... ]
         │
         ├─── Roll 1: "free" (prob = 0.08)
         ├─── Roll 2: "cash" (prob = 0.07)
         ├─── Roll 3: "free" (prob = 0.08)
         └─── Document generated: { "free": 2, "cash": 1 }
```

In log-space, the multinomial coefficient depends only on the document length $\sum x_j$ and does NOT depend on the class $c$. Therefore, it can be dropped as a constant during $\arg\max$ comparison:

$$\log P(\mathbf{x} \mid y = c) \propto \log P(y = c) + \sum_{j=1}^{D} x_j \ln(p_{cj})$$

Notice that this is a **linear model** in log-space! $\sum x_j \ln(p_{cj}) = \mathbf{w}_c^T \mathbf{x} + b_c$, making `MultinomialNB` as fast as linear models during live scoring!

## 2. Vectorization: CountVectorizer vs. TfidfVectorizer

```
  ┌────────────────────────────────────┬────────────────────────────────────┐
  │         CountVectorizer            │          TfidfVectorizer           │
  ├────────────────────────────────────┼────────────────────────────────────┤
  │ Produces raw integer frequencies   │ Produces normalized continuous     │
  │ x_j in {0, 1, 2, ...}.             │ fractional weights in [0.0, 1.0].  │
  │ Strictly adheres to discrete PMF.  │ Dampens common English terms       │
  │ Susceptible to document length     │ via Inverse Document Frequency.    │
  │ distortions (long docs dominate).  │ Empirically outperforms CountVec.  │
  └────────────────────────────────────┴────────────────────────────────────┘
```

### Can MultinomialNB Accept Fractional TF-IDF Floats?
**YES.** While theoretical multinomial distributions require discrete counts, Scikit-Learn's `MultinomialNB` implements the linear dot product:

$$\hat{y} = \arg\max_c \left[ \log P(y=c) + \mathbf{x}^T \log \mathbf{p}_c \right]$$

Because $\mathbf{x}^T \log \mathbf{p}_c$ operates smoothly on any non-negative continuous vector, fractional TF-IDF weights work mathematically and provide **superior real-world classification accuracy**.

### Production Tip: `sublinear_tf=True`
In spam detection, a spammer might repeat *"viagra"* $50$ times in one email. Under linear TF, this token has $50\times$ the voting power.
Enabling `sublinear_tf=True` replaces raw term frequency $tf$ with:

$$tf_{\text{sublinear}} = 1 + \ln(tf) \quad (\text{for } tf > 0)$$

A word appearing $50$ times has $\approx 4.9\times$ weight instead of $50\times$, preventing single-word hijacking.

## 3. The Negative Value Catastrophe (Common Production Crash)

`MultinomialNB` has a strict mathematical precondition: **all input features must be non-negative ($x_j \ge 0$)**.

### The Disaster Scenario:
```python
# 🚨 FATAL PIPELINE MISTAKE:
pipeline = Pipeline([
    ('tfidf', TfidfVectorizer()),
    ('scaler', StandardScaler()),  # CRASH! Subtracts mean, creating negative z-scores!
    ('nb', MultinomialNB())
])
pipeline.fit(X_train, y_train)
```

```
ValueError: Negative values in data passed to MultinomialNB (input X)
```

### The Architectural Rules:
1. **NEVER use `StandardScaler()`** before `MultinomialNB` or `ComplementNB`.
2. TF-IDF features are already normalized ($\|x\|_2 = 1.0$) and bounded within $[0, 1]$. **No additional scaler is required**.
3. If scaling count data, use `MaxAbsScaler()` or `MinMaxScaler()`, which preserve the non-negative domain.
